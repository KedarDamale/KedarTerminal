The clean generated wallpaper is tracked in `assets/landscape.png`. Asset
preparation produced 46 PNGs at 1280 × 800 with 22 reveal steps per language.
Both complete name frames were visually inspected; Marathi uses RAQM shaping
and the installed Noto Sans Devanagari font. The English art is a custom 5×7
sculpted block design inspired by the reference, not a pixel-exact extraction.

Automated tests cover phase order over ten cycles, late-frame timing,
monotonic reveal/erase, settings validation, asset integrity, protection of
unrelated files, backup/restore, suppression of repeated hold frames, bounded
failure fallback, process-tree sampling and PTY startup readiness.
The Python wheel builds successfully and includes the wallpaper and profiles.

Real smoke tests used locally extracted Ubuntu packages: Kitty 0.45.0,
Fish 4.2.1 and Starship 1.22.1. These are in the ignored `.cache/toolchain`;
the system package installation could not proceed without interactive sudo
authentication. Kitty background updates, interactive command execution,
stop/start/restart/static controls, window closure and runtime cleanup passed
under Xvfb with software OpenGL. Testing found and fixed Kitty 0.45 CLI's
omission of `cscaled`; remote updates now retain the configured layout.

## Exploratory resource samples

A single 12-second sample per case, at 0.5-second intervals, produced:

| Virtual-display case | Mean CPU, one core % | Mean RSS MiB |
|---|---:|---:|
| Ptyxis with default settings + Bash | 13.03 | 270.93 |
| Kedar Kitty static + Fish + controller | 57.77 | 243.78 |
| Kedar Kitty animated + Fish + controller | 232.24 | 251.22 |

An earlier static/animated pair produced 17.50% / 114.79% CPU, showing that
these short software-rendering samples are variable. **The CPU acceptance
target is not met in this test environment.** No target-hardware CPU, GPU,
battery, typing latency or GUI-startup claim follows from these samples.
Ptyxis used isolated default settings; it was not the user's already-open
desktop terminal. Window sizing and application stacks differ. RSS includes
shared pages multiple times and excludes VRAM. Measurements include each
launched process tree, not just the animation controller. Raw local CSV/JSON
files are kept in ignored `reports/` files, generated by the shipped tools.

Five-run PTY shell-startup medians were 177.35 ms for the existing Bash startup
and 12.74 ms for the isolated Fish profile. These are different shell profiles,
warm samples and not a measurement of animation-induced startup overhead.

## Repeating the real renderer test

With Kitty, Fish, Starship and Xvfb installed, prepare the checkout-local profile
as described in `SETUP.md`, then:

```bash
mkdir -p .cache/runtime .cache/data
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 \
    XDG_RUNTIME_DIR="$PWD/.cache/runtime" \
    XDG_DATA_HOME="$PWD/.cache/data" \
    XDG_CACHE_HOME="$PWD/.cache" \
    STARSHIP_CACHE="$PWD/.cache/starship" \
    LIBGL_ALWAYS_SOFTWARE=1 \
    xvfb-run -a python3 tests/smoke_kitty.py
```

Add `--baseline` to the smoke script when Ptyxis and `dbus-run-session` are
available. It uses a separate default-settings Ptyxis instance. For an actual
desktop comparison use `PERFORMANCE.md` and collect repeated matched workloads.
Manual checks for selection, completion menus, resizing, alternate-screen
programs, HiDPI, tmux and prolonged playback remain outstanding.
